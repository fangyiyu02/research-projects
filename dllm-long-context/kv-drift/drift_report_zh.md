# 长文本下 dLLM KV Drift 观测实验报告

UltraLLaDA-8B · 4K–64K 上下文 · 2026-09

---

## 1. 我们想回答什么

Elastic-Cache（ICLR 2026）观察到 dLLM 解码时 KV 状态"漂移"（每一步都在微变），
并据此设计缓存刷新策略——但它所有观测都在 **1.5K 长度以内**做的。我们的两个问题：

1. **长文本（4K–64K）下，KV drift 长什么样？** 短文本的规律还成立吗？
2. **层和步两个维度是否耦合？** 即"某些步 × 某些层"是否存在特殊行为，
   还是层规律和步规律各管各的。

## 2. 测的是什么（大白话）

**KV drift 的定义**：dLLM 与普通自回归模型不同——它每一步解码都会**重算
全部 token 的 K、V**，而且由于双向注意力，已解码 token 的 K/V 会随着新
token 的出现而**继续变化**。KV drift 就是这个变化量：

> **同一层、同一位置的 K/V 向量，在第 t 步与第 t−1 步之间差了多少。**

差分方向沿**步（时间）轴**——层只是分组维度（每层各测各的，摆在一起
比较），不做层与层之间的差分。这与 Elastic-Cache 论文 Def A.7 的定义
一致（它用 L2 差、图上画余弦；我们两个口径都记，见下表）。另外我们
补了一个论文没有的口径：与**第 0 步**比的累积总漂移（total_K/V），
回答"缓存从头放到尾总共坏了多少"。

drift 为什么重要：缓存的本质是"存旧值、以后复用"——K/V 漂得越快，
缓存过期越快、越需要刷新；漂得慢的地方缓存可以久放。所以 drift 地形图
就是刷新策略的依据。

模型解码时每一步都做一次全量前向。我们在每层的 K、V 刚算出来的地方装了
"探头"，把这一步的值和上一步的值做对比：

| 记录量 | 大白话 | 数值含义 |
|---|---|---|
| sim_K / sim_V | 这一步和上一步比，K/V 的**方向**变了多少 | 1 = 完全没变；越小变得越多 |
| rel_K / rel_V | 这一步和上一步比，K/V 的**幅度**挪了百分之几 | 0 = 没动；0.05 = 挪了自身长度的 5% |
| total_K / total_V | 和**第 0 步**比，到现在总共漂了多少 | "从头到尾完全不刷缓存"的损耗上界 |
| heat_K | 上面的 sim_K 不做位置平均，逐 token 保留 | 看漂移集中在序列的哪些位置 |
| step_time / peak_mem_gb | 每步耗时、显存峰值 | 排期与 64K 可行性判断 |

每个量都是一张 **[512 步 × 32 层] 的表**，即"每一步、每一层各漂了多少"的地形图。

关键测量原则（保证测的是干净的东西）：
- **no-cache 全量重算**下测——模型每步老老实实全算，测到的是模型内生的
  漂移，不混缓存陈旧的误差；
- 探头只**旁路记录**，不回流模型计算，解码结果与裸跑逐位一致；
- 解码用 **LLaDA 官方 generate.py 原样调用**（锁定 commit，零修改），
  不自己造解码逻辑。

## 3. 工具链：每个文件是干嘛的

| 文件 | 作用 | 输入 | 输出 |
|---|---|---|---|
| `drift_recorder.py` | 核心库（不直接运行）。往模型每层挂 hook，自动识别"新的一步开始了"，在线算上面五个量 | 被 run_drift 调用 | — |
| `run_drift.py` | 跑一条样本：加载模型和 prompt → 挂探头 → 调官方 generate() → 落盘 | `--model` 模型路径；`--prompt-file` RULER 的 .pt；`--sample-idx` 取第几条；`--gen-len 512`；`--steps 512`（1 token/步）；`--block-length 32`；`--heatmap-stride 8`；`--buffers gpu/cpu`（64K 用 cpu） | 每条样本一个 `.npz`（五个矩阵）+ 一个 `.json`（配置、步数、耗时、显存留档） |
| `test_smoke.py` | 冒烟自检：用假模型跑 5 步，验证探头、自动分步、落盘格式都正常。**每次改完代码先跑它** | 无参数 | 两行 OK + 测试图 |
| `plot_drift.py` | 单样本出图：drift 热图（步×层）、层曲线、累积漂移曲线；同目录多样本叠图看一致性 | 若干 .npz | 每样本 3 张 png + 叠图 |
| `analyze_lengths.py` | 跨长度聚合：把 4k/8k/…目录各自平均，画"层曲线随长度变化"“耗时随长度"等对比图 + 汇总表 | results 根目录 | summary/ 下 5 张对比图 + stdout 表 |
| `coupling_map.py`（机器上叫 coupling_map_v.py） | 耦合分析主图：对每档的 drift 场做 SVD，出三联图【实测场 / 最优"层×步可分离"近似 / 残差=耦合本体】，K、V 各一套 | 各长度目录 | 每档 4 张 png + 耦合指数 |
| `check_lengths.py` | 统一口径的数字表：去掉开场段后的耦合指数、爆发/稳态强度比、块边界周期检验 | 无参数（内置路径） | stdout 一张表（见 §6） |
| `run_64k.sh` | 64K 批跑脚本：`--buffers cpu`（观测数据搬去内存，省 ~40GB 显存），第 0 条跑完自动查显存水位再续跑 | 环境变量 ULTRALLADA_MODEL_PATH | 同 run_drift |

## 4. 实验设置

| 项 | 设定 |
|---|---|
| 模型 / 硬件 | UltraLLaDA-8B（bf16），单卡 RTX PRO 6000 96GB |
| 解码 | LLaDA 官方算法：半自回归分块（block 32）+ 低置信度重掩码，temperature 0，steps=512（每步 1 token），gen 512 |
| 数据 | RULER `niah_single_2`（essay 填充，自然文本）。数据先过验收：无周期、8-gram 基本不重复——重复噪声填充（如 niah_single_1）会人为压低漂移，被排除出主矩阵 |
| 长度矩阵 | prefill 4K / 8K / 16K / 32K 各 **10 条**样本，64K **2 条**（试水） |
| 显存 | 4–32K 观测 buffer 驻显存（32K 实测峰值 59.06 GB，无需分块）；64K 用 `--buffers cpu` 把 buffer 搬去内存 |

## 5. 实验流程（实际执行顺序）

1. `test_smoke.py` 冒烟 → 核对三个适配点（blocks 路径、MASK id、官方 generate 导入）；
2. 4K 首样本单跑自检（步数=512、显存、热图形状正常）→ 批量 10 条；
3. 同法跑 8K / 16K / 32K 各 10 条；64K 用 run_64k.sh 跑 2 条；
4. `plot_drift.py` 各档出图 → `coupling_map.py` 出 K/V 耦合三联图 →
   `check_lengths.py` 出统一口径数字表；
5. 数据全程留档：每条样本 npz+json，图集中在 summary/。

## 6. 结果：五条观测

### ① 层的规律是"开关"，不是"斜坡"
前 15 层的 KV 几乎纹丝不动；第 16 层附近突然跳变；深半区大幅漂移，
峰值在 19–22 层，更深反而回落（驼峰形）。短文本论文说的"越深漂得越多的
平缓斜坡"在这里不成立——是断崖。
**含义：整个网络前一半的缓存基本可以白拿，不用刷。**

### ② 时间的规律是"开场闹、之后静"，且越长反差越大
头 20–30 步剧烈动荡，之后一路安静到底。开场/稳态的强度比随长度从
2.9 倍涨到 9.5 倍。原先猜想的"每 32 步块边界会抖一下"经检验**不存在**
（尖刺相位随机分布）。4K 还有一个独有现象：生成末段（约 450 步后）出现
二次漂移带，16K 起消失。

### ③ 上下文越长，KV 越"懒"（最干净的一条）
稳态期漂移强度随长度**单调下降约 40%**（4K→32K，64K 也在趋势线上）。
直觉：几万个 token 共同决定的 KV，新解出的几个 token 撼不动它。
**含义：文本越长，缓存保质期越长，能省的计算越多——这正是长文本推理
加速最想要的性质，且短文本实验根本看不到。**

统一口径数字表（check_lengths.py 输出）：

| 长度 | n | 耦合(全程) | 耦合(去开场) | 开场强度 | 稳态强度 | 开场/稳态 |
|---|---|---|---|---|---|---|
| 4K | 10 | 0.147 | 0.137 | 0.00114 | 0.00040 | 2.9× |
| 8K | 10 | 0.156 | 0.126 | 0.00117 | 0.00037 | 3.2× |
| 16K | 10 | 0.090 | 0.149 | 0.00221 | 0.00032 | 6.9× |
| 32K | 10 | 0.054 | 0.098 | 0.00226 | 0.00024 | 9.5× |
| 64K | 2 | 0.083 | 0.054 | 0.00157 | 0.00018 | 8.7×（n=2 仅供参考） |

### ④ 耦合：存在、能定位，但不是主角
定义：drift 地形图若能拆成"一条层曲线 × 一条步曲线"，就叫无耦合；
拆不掉的部分就是耦合。测出来：**85–90% 的地形能用两条曲线解释，
耦合占 10–15%**（稳态口径，4K–16K 约 0.13–0.15，32K 降至 ~0.10）。
耦合的住址找到了：K 集中在相变层带（16–18 层）× 开场段。
注意"全程口径"的指数随长度单调下降是**假象**——是开场爆发越来越占
主导把比例拉低，不是稳态耦合真变小（表中两列对比即证据）。

### ⑤ K 和 V：同一族形状，不同参数
V 的骨架与 K 一致（前段平、中段变、驼峰、开场爆发），但三处系统性不同：
V 的漂移量级是 K 的 **2–3 倍**；V 的驼峰**深移**到 24–25 层（K 在 19–22）；
V 的相变是从 ~13 层起的**缓坡**（K 是 15–16 的断崖）。耦合残差的位置也
不同（K 在相变带、V 在驼峰层）。
**含义：刷新策略应 K/V 非对称——V 刷得勤、K 刷得稀，各持一条层权重。**

## 7. 结论与下一步

一句话总结：**长文本下 KV drift 的图景 = 前半层静止 + 开场后静默 +
越长越稳定 + K/V 同构不同参；耦合存在但只占一成多。**
省算空间比短文本文献暗示的更大，且"该在哪省"（哪些层、哪些步、K 还是 V）
已经有了完整地图。

由此指向的方法方向（下一轮实验）：利用地图做**离线 profile 一次、推理时
零开销查表**的静态刷新调度——长度自适应（观测③）、两阶段（观测②）、
驼峰靶向且 K/V 非对称（观测①⑤）。相比现有方法的额外优势：Elastic-Cache/
Polestar 的触发器依赖注意力权重、与 FlashAttention 冲突，官方实现在 32K
直接显存溢出；我们的方案完全不碰注意力。验证路径：按地图冻结/刷新跑推理，
对比 no-cache 与 Fast-dLLM 的准确率+吞吐（NIAH 自带标准答案，可直接当
质量信号）。

## 8. 已知局限（诚实清单）

- 64K 仅 2 条样本，该档所有数字仅供参考，需补到 6–10 条；
- 32K 的 V 侧三联图缺一张（不影响结论，补跑即可）；
- 单任务（niah_single_2）单模型：跨任务（qa_1）迁移性、结构是否为
  UltraLLaDA 特有（对照原版 LLaDA 短文本）尚未验证——是静态调度方案
  最大的风险点，列为下一轮必做对照；
- 全部结论基于官方解码配置（1 tok/步）；并行解码（多 tok/步）下漂移
  会更大，地图数值需重标定（结构预计不变）。
